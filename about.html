What is GHost Engine?

GHost Engine is a custom real-time 3D graphics engine built from scratch in C++20 using Vulkan 1.3. It started as an academic project at ESAT (Unit 46: Advanced Rendering and Visualization, 2025/2026) and has grown into a complete rendering framework covering techniques used in modern production games.

The engine ships as a static library. User code only includes ghost.h — it never touches Vulkan, GLFW, or OpenAL headers directly. A suite of eleven demo executables (from a basic triangle up to a playable Pac-Man game built entirely in Lua) validate the API and showcase the rendering quality.

Build system: Premake5 (Visual Studio 2022). Dependency management: Conan 2. The project targets zero warnings at /W4 /WX with full RAII resource management.

Engine Features

  • Vulkan 1.3 backend (RAII HPP)
  • Deferred rendering pipeline
  • Cook-Torrance PBR BRDF
  • Cascaded Shadow Maps (3 cascades)
  • Spot & point light shadows
  • HDR + ACES / Hable tonemapping
  • Bindless texture descriptor heap
  • VulkanMemoryAllocator (VMA)
  • ECS with generational entity IDs
  • Parent-child transform hierarchy
  • Lua 5.4 scripting via Sol2
  • GHJobSystem thread pool (C++20)
  • 5-band LOD streaming system
  • AABB frustum culling
  • Procedural terrain (fBm + erosion)
  • Infinite terrain chunk streaming
  • OpenAL Soft 3D spatial audio
  • BranchingSound adaptive music
  • ImGui editor + dual viewport
  • Scene serialization (.ghscene JSON)
  • Play / Pause / Stop workflow
  • CPU/GPU profiler (UDP stream)

Architecture Overview

The renderer implements four passes each frame: a shadow pass that fills the cascaded shadow atlas, a GBuffer pass that writes albedo, world-space normal, packed material data, and depth, a full-screen lighting pass that evaluates the Cook-Torrance BRDF for each active light, and a post-processing pass that applies exposure scaling, tonemapping, and gamma correction.

The ECS layer uses 32-bit generational entity handles. Component data is stored in contiguous vectors (SoA layout) for cache-friendly iteration. Lua scripts attach to entities via ScriptComponent and receive a full Transform/Input/Light API through Sol2 bindings.
