Deferred Rendering & Cook-Torrance BRDF

Posted on April 10, 2026 · Tags: deferred · pbr · gbuffer · brdf · vulkan

GHost Engine uses a fully deferred shading pipeline. Instead of evaluating lighting for every triangle during the geometry draw call, geometry is drawn once into a set of intermediate textures (the GBuffer). A later full-screen pass then reads those textures and evaluates lighting per pixel — regardless of how many lights are in the scene or how complex the geometry is.

The cost model changes from O(triangles × lights) in forward rendering to O(pixels × lights) in deferred — a significant saving for dynamic, multi-light scenes.

The Four-Pass Frame

🖼 IMAGE: Full frame pipeline flowchart Four boxes connected by arrows: Shadow Pass → GBuffer Pass → Lighting Pass → Post-Process Pass. Each box lists its inputs and outputs (e.g. GBuffer Pass outputs albedo/normal/material/depth textures).

Pass 1 — Shadow Pass

Before any geometry is drawn for the final image, scene geometry is re-drawn from the directional light's perspective into a depth-only shadow atlas. Ghost Engine uses Cascaded Shadow Maps with three cascades at 2048×2048 each. No colour attachments are active — the vertex shader outputs only gl_Position in light space and the fragment shader is unused.

A pipeline barrier transitions the depth image from DEPTH_STENCIL_ATTACHMENT_OPTIMAL to SHADER_READ_ONLY_OPTIMAL before the lighting pass can sample it.

Pass 2 — GBuffer Fill

All opaque scene entities are drawn into four simultaneous render targets via a single VkRenderPass with four colour attachments and one depth attachment.

Attachment Format Content
AlbedoR8G8B8A8_SRGBBase colour × tint
NormalR16G16B16A16_SFLOATWorld-space normal (TBN-transformed)
MaterialR8G8B8A8_UNORMMetallic (R), Roughness (G), AO (B)
DepthD32_SFLOATHardware depth, reused for position reconstruction

Each draw call pushes the model matrix (64 bytes) and a material index (4 bytes) as push constants. The fragment shader reads textures by integer index from the bindless descriptor heap — no per-draw descriptor rebind is needed.

Pass 3 — Lighting (Cook-Torrance BRDF)

A single full-screen triangle (generated in the vertex shader from gl_VertexIndex, no vertex buffer required) drives the lighting fragment shader. The shader:

  1. Reads the four GBuffer textures.
  2. Reconstructs world-space position from the depth buffer and the inverse view-projection matrix.
  3. Iterates over all active GPU lights from the GPULightData UBO.
  4. Evaluates the Cook-Torrance BRDF for each light.
  5. Applies PCF-filtered shadow attenuation from the CSM atlas.
  6. Writes the accumulated HDR radiance to a R16G16B16A16_SFLOAT target.

The Cook-Torrance BRDF

The reflectance equation implemented in the lighting shader: 

// Lo = outgoing radiance at the fragment
Lo += (kd * albedo/PI + ks * (D * F * G) / (4 * NdotV * NdotL))
       * Li * NdotL * shadow;

Where:

  • D — GGX Normal Distribution Function (controls highlight shape).
  • F — Schlick Fresnel approximation (reflectance at grazing angles).
  • G — Smith geometry function (micro-surface shadowing/masking).
  • kd = (1-F) * (1-metallic) — diffuse energy fraction.
  • ks = F — specular energy fraction.
  • Li — light radiance, attenuated by distance for point/spot lights.
  • shadow — PCF occlusion factor [0,1] from the shadow atlas.
// GGX Normal Distribution Function
float ggx(float NdotH, float roughness) {
    float a  = roughness * roughness;
    float a2 = a * a;
    float d  = NdotH * NdotH * (a2 - 1.0) + 1.0;
    return a2 / (PI * d * d);
}

// Schlick Fresnel
vec3 schlick(float VdotH, vec3 F0) {
    return F0 + (1.0 - F0) * pow(1.0 - VdotH, 5.0);
}

// Smith GGX Geometry
float smithG1(float NdotX, float roughness) {
    float k = roughness * roughness * 0.5;
    return NdotX / (NdotX * (1.0 - k) + k);
}
float geometry(float NdotV, float NdotL, float roughness) {
    return smithG1(NdotV, roughness) * smithG1(NdotL, roughness);
}

// Base reflectance: 0.04 for dielectrics, albedo for metals
vec3 F0 = mix(vec3(0.04), albedo, metallic);

Position is reconstructed without a dedicated position GBuffer attachment, saving memory bandwidth: 

// Reconstruct world position from depth + inverse VP
vec4 clipPos  = vec4(uv * 2.0 - 1.0, depth, 1.0);
vec4 worldPos = invViewProj * clipPos;
worldPos /= worldPos.w;  // perspective divide

Pass 4 — Post-Processing

The HDR colour attachment is consumed by the post-processing pass, which applies exposure scaling, tonemapping (ACES by default), and gamma correction before presenting to the swapchain. See the dedicated HDR & Tonemapping post for details.

Why Deferred over Forward?

During development, a forward renderer was benchmarked with 8 dynamic lights against the target scene complexity. Cost scaled as O(triangles × lights); adding a fifth light measurably reduced frame rate. Deferred rendering moved the lighting cost to a fixed-size screen-space pass — adding more lights only adds cost in the lighting pass, not in the geometry pass. For scenes with many simultaneous dynamic lights, this is a decisive advantage.
