LOD Streaming & Frustum Culling

Posted on May 10, 2026 · Tags: lod · streaming · frustum · performance · vulkan

Keeping frame time under 16 ms in complex scenes requires more than a fast renderer — it requires not rendering things that don't matter. GHost Engine combines two orthogonal strategies: frustum culling skips entities that are off screen entirely, and LOD streaming reduces texture resolution for distant objects that are on screen but too small to warrant full-quality assets.

The gh_streaming Configuration

Streaming is configured through gh_streaming, which holds a vector of distance-band descriptors (lod structs) and a global config: 

// From gh_streaming.h
struct lod {
    float distance    = 10.0f; // far boundary of this band (world units)
    int   texture_mip_level = 0;  // mip bias — 0 = full resolution
    int   mesh_lod_level    = 0;  // reserved for future mesh simplification
};

// Default 5-band configuration:
// Band 0: [  0, 10) → mip 0  (full resolution)
// Band 1: [ 10, 30) → mip 1  (half resolution)
// Band 2: [ 30, 80) → mip 2  (quarter resolution)
// Band 3: [80, 200) → mip 3
// Band 4: [200, ∞ ) → mip 4  (culled if limit_render_distance_by_lod = true)

Frustum Culling

Six frustum planes are extracted from the view-projection matrix each frame using the Gribb-Hartmann method. Each plane is then normalised: 

// Extract the 6 frustum planes from VP (column-major GLM matrix)
static Frustum extractFrustum(const glm::mat4& vp) {
    Frustum f;
    f.planes[0] = vp[3] + vp[0]; // left
    f.planes[1] = vp[3] - vp[0]; // right
    f.planes[2] = vp[3] + vp[1]; // bottom
    f.planes[3] = vp[3] - vp[1]; // top
    f.planes[4] = vp[3] + vp[2]; // near
    f.planes[5] = vp[3] - vp[2]; // far

    // Normalise each plane (divide by XYZ length)
    for (auto& p : f.planes) {
        float len = glm::length(glm::vec3(p));
        p /= len;
    }
    return f;
}

An entity's world-space AABB is tested against all six planes. Rejection happens on the first plane where the AABB's positive vertex (the corner most in the plane's positive half-space) is behind the plane: 

static bool aabbInFrustum(const Frustum& f,
                           const GHModel::AABB& local,
                           const glm::mat4& worldMat) {
    // Transform AABB corners to world space
    // ...
    for (int i = 0; i < 6; ++i) {
        glm::vec3 n = glm::vec3(f.planes[i]);
        float d = f.planes[i].w;
        // Positive-vertex test: take the corner most aligned with the plane normal
        glm::vec3 pv = worldMin;
        if (n.x >= 0) pv.x = worldMax.x;
        if (n.y >= 0) pv.y = worldMax.y;
        if (n.z >= 0) pv.z = worldMax.z;
        if (glm::dot(n, pv) + d < 0.0f) return false; // fully outside
    }
    return true;
}

The Priority Multiplier System

A fixed LOD distance (e.g. switch to mip 1 at 10 m) treats a 0.5 m rock and a 30 m building identically, even though the building is still visually large at 10 m. The priority system fixes this by scaling the distance thresholds per entity based on its AABB diagonal: 

// Auto-priority: derived from mesh AABB diagonal
float multiplier = clamp(
    aabb_diagonal / priority_reference_size, // reference = 5 m by default
    priority_min_multiplier,  // 0.25
    priority_max_multiplier   // 4.0
);

// Effective distance for LOD evaluation:
float effectiveDist = distance / multiplier;

// Example:
// 30 m building (diagonal ~37 m): multiplier = min(37/5, 4.0) = 4.0
//   → switches to mip 1 at 40 m instead of 10 m
// 0.5 m rock (diagonal ~0.7 m):  multiplier = max(0.7/5, 0.25) = 0.25
//   → switches to mip 1 at 2.5 m instead of 10 m

Manual override presets are also available per entity: StreamingPriority::High (×3.0), StreamingPriority::Normal (×1.0), StreamingPriority::Low (×0.4).

Per-Entity Streaming State

The renderer caches per-entity streaming data in an unordered_map<uint32_t, EntityStreamingState>: 

struct EntityStreamingState {
    float lodBias       = 0.0f;   // current texture mip bias
    bool  lodVisible    = false;  // passed frustum test?
    int   activeLOD     = 0;      // current band index
    float lastDistance  = 0.0f;  // last evaluated distance
    float priorityMultiplier = 1.0f;
    bool  priorityReady = false;  // multiplier initialised from mesh AABB?
};

Update Interval

LOD re-evaluation runs every updateInterval = 0.1 s (10 times per second), not every frame. The timer accumulates dt; when it exceeds the interval, all entity states are updated and the timer resets. This avoids spending per-entity frustum and distance calculations (which can be non-trivial for large scenes) on every single frame.

Streaming Config Flags

struct StreamingConfig {
    bool is_streaming               = true;
    bool frustum_culling            = true;
    bool streaming_on_play_camera   = true;
    bool streaming_on_editor        = false; // culling disabled in editor by default
    bool disable_frustum_culling_on_editor = true;
    bool limit_render_distance_by_lod      = true; // cull beyond last LOD band
    bool priority_auto_enabled      = true;
    float priority_reference_size   = 5.0f;
    uint32_t anisotropic_filtering_level = 2; // 1=off, 2=x4, 3=x16
};

VRAM Pressure

If VRAM usage exceeds vramPressureThreshold (75% by default), the streaming system narrows its hysteresis window — reducing how many LOD levels stay resident in GPU memory simultaneously from 3 to 2. This provides a safety valve against VRAM exhaustion in scenes with unusually large or numerous texture assets.
