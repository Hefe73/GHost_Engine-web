Lua Scripting via Sol2

Posted on May 20, 2026 · Tags: lua · sol2 · scripting · ecs · c++20

One of the core requirements of the engine brief was user-authored game logic that runs without recompiling the engine. GHost Engine meets this with an embedded Lua 5.4 interpreter managed by Sol2 3.3 — a header-only C++ binding library that provides zero-overhead, type-safe bridges between C++ classes and Lua usertypes.

Lua was chosen over a custom scripting language because it is the de-facto scripting language of the games industry (World of Warcraft, Roblox, CryEngine, and many others), has a tiny runtime footprint (around 200 KB), and Sol2 makes the C++ binding almost trivial to maintain.

Binding C++ Types to Lua

At engine initialisation, GHScripting::init() registers every exposed type as a Sol2 usertype. Each method or property becomes a named member in Lua: 

// Vec3 — registered as glm::vec3 proxy
lua.new_usertype<Vec3>("Vec3",
    sol::constructors<Vec3(), Vec3(float,float,float)>(),
    "x",         &Vec3::x,
    "y",         &Vec3::y,
    "z",         &Vec3::z,
    "normalize", [](Vec3& v){ return glm::normalize(v); },
    "dot",       [](const Vec3& a, const Vec3& b){ return glm::dot(a,b); },
    "length",    [](const Vec3& v){ return glm::length(v); },
    sol::meta_function::addition,       [](Vec3 a, Vec3 b){ return a+b; },
    sol::meta_function::subtraction,    [](Vec3 a, Vec3 b){ return a-b; },
    sol::meta_function::multiplication, [](Vec3 v, float s){ return v*s; }
);
// Transform — read/write position, rotation, scale; translate helper
lua.new_usertype<TransformProxy>("Transform",
    "position",  sol::property(&TransformProxy::getPos, &TransformProxy::setPos),
    "rotation",  sol::property(&TransformProxy::getRot, &TransformProxy::setRot),
    "scale",     sol::property(&TransformProxy::getScale, &TransformProxy::setScale),
    "translate", &TransformProxy::translate
);

// Input — keyboard and mouse queries
lua.new_usertype<InputProxy>("Input",
    "isKeyDown",         &InputProxy::isKeyDown,
    "isMouseButtonDown", &InputProxy::isMouseButtonDown,
    "getMouseDelta",     &InputProxy::getMouseDelta
);

// Light — colour, intensity, range
lua.new_usertype<LightProxy>("Light",
    "setColor",     &LightProxy::setColor,
    "setIntensity", &LightProxy::setIntensity,
    "setRange",     &LightProxy::setRange
);

The this Global and Named Entity Exposure

Before calling each entity's Lua update(dt) function, the scripting system sets up two things:

  1. this — a Lua global pointing to the current entity's proxy, so the script can access its own transform without any lookup.
  2. Named entity globals — for every entity with a DebugNameComponent, a Lua global is created using that name (e.g. Player, Door). Scripts can reference other entities by name directly. 
// C++ side — before calling script update
lua["this"] = entityProxy;

// Expose all named entities as globals
for (auto& e : scene.entities) {
    if (scene.DebugNameComp.has(e)) {
        auto name = scene.DebugNameComp.getName(e);
        lua[name] = makeEntityProxy(e, scene);
    }
}

Writing a Script

A Lua script attached via ScriptComponent must define an update(dt) function. The engine calls it once per frame during Scene::update(): 

-- assets/scripts/player.lua

local speed     = 5.0
local turnSpeed = 2.0

function update(dt)
    -- Move forward/backward
    if Input.isKeyDown("W") then
        this.transform.translate(Vec3(0, 0, speed * dt))
    end
    if Input.isKeyDown("S") then
        this.transform.translate(Vec3(0, 0, -speed * dt))
    end

    -- Rotate left/right
    if Input.isKeyDown("A") then
        local r = this.transform.rotation
        this.transform.rotation = Vec3(r.x, r.y - turnSpeed * dt, r.z)
    end
    if Input.isKeyDown("D") then
        local r = this.transform.rotation
        this.transform.rotation = Vec3(r.x, r.y + turnSpeed * dt, r.z)
    end
end

Interacting with Other Entities

Because named entities are exposed as globals, any script can modify any other entity without any explicit lookup API: 

-- In enemy.lua — change a light entity's colour based on game state
function update(dt)
    if hp < 20 then
        -- WarningLight is the DebugName of a light entity in the scene
        WarningLight.light.setColor(1.0, 0.0, 0.0)  -- red
        WarningLight.light.setIntensity(3.0)
    else
        WarningLight.light.setColor(1.0, 1.0, 1.0)  -- white
        WarningLight.light.setIntensity(1.0)
    end
end

Hot-Reload

The inspector panel shows a Reload button for each ScriptComponent. Clicking it calls GHScripting::runScript(path) again, which re-executes the Lua file in the existing interpreter state — redefining all functions including update(). The new behaviour takes effect on the very next frame without stopping the scene or restarting the engine.

The Pacman Demo

The Pacman demo is the most complete example of the scripting system in practice. The entire game — player movement, ghost AI, pellet collection, score tracking, power-up logic, and game-over detection — is implemented exclusively in Lua scripts attached to entities. Not a single line of C++ was written or modified for the game. This validates the scripting API as a complete game development interface.
