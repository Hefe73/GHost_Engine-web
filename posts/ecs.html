ECS Architecture: Entities, Components & Systems

Posted on March 28, 2026 · Tags: ecs · architecture · c++20 · engine

GHost Engine's game-object model is built on a classic Entity-Component-System (ECS) pattern. Rather than deep inheritance hierarchies, every object in the world is a lightweight integer ID (the entity) with data attached through independent component managers. This separation keeps memory access patterns cache-friendly and makes it trivial to add new behaviour without touching existing code.

Generational Entity IDs

An Entity is a 32-bit unsigned integer split into two fields: 24 bits of index and 8 bits of generation. The generation counter solves the classic "dangling handle" problem: when an entity is destroyed and its slot recycled, the generation increments. Any old handle that still holds the previous generation will be rejected by EntityManager::alive().

🖼 IMAGE: Entity ID bit layout Diagram showing the 32-bit word: bits 31–8 = index (24 bits), bits 7–0 = generation (8 bits) 
// From gh_entity.h
struct Entity
{
    uint32_t id = 0;

    uint32_t index()      const { return id & ENTITY_INDEX_MASK; }
    uint32_t generation() const { return (id >> ENTITY_INDEX_BITS) & ENTITY_GENERATION_MASK; }

    bool isNil()                       const { return id == 0; }
    bool operator==(const Entity& e)   const { return id == e.id; }
};

EntityManager::create() either recycles a slot from the free list or appends a new one. destroy(e) increments the slot's generation and pushes the index back onto a std::deque, ready for reuse.

Component Managers (SoA Layout)

Each component type is owned by a dedicated manager that stores data in a contiguous std::vector — one array per field (Structure of Arrays). When a system iterates over a single component type (e.g. all positions for frustum culling), it touches only that field's memory, keeping the CPU cache hot.

The Scene class owns all component managers directly: 

// From gh_scene.h — Scene component managers
TransformComponentECS  TransformComp;
MeshComponent          MeshComp;
TextureComponent       TextureComp;
BillboardComponent     BillboardComp;
SoundComponent         SoundComp;
LightComponent         LightComp;
DebugNameComponent     DebugNameComp;
ScriptComponent        ScriptComp;
🖼 IMAGE: SoA vs AoS comparison diagram Left: AoS — array of structs [{pos,rot,scale}, {pos,rot,scale}, ...] with interleaved cache misses. Right: SoA — three separate contiguous arrays [pos[], rot[], scale[]] with cache-friendly access.

Creating and Using Entities

Entities are created through the Scene API. Components are attached via the corresponding manager. Destroying an entity automatically marks it as dead; the slot is recycled when the free list grows past 1024 entries. 

// Create an entity and attach components
gh::Entity e = scene->AddEntity();

// Attach a debug name
scene->DebugNameComp.setName(e, "Player");

// Attach a transform (position, rotation, scale)
scene->TransformComp.setPosition(e, { 0.f, 1.f, 0.f });
scene->TransformComp.setScale(e, { 1.f, 1.f, 1.f });

// Attach a mesh
scene->MeshComp.setModel(e, myModel);

// Attach a Lua script
scene->ScriptComp.setScript(e, "assets/scripts/player.lua");

// Remove the entity later
scene->RemoveEntity(e);

Transform Hierarchy

TransformComponentECS supports parent-child relationships through a parentID field stored per entity. getWorldMatrix(entity) walks up the parent chain, multiplying local matrices together. World matrices are cached with a dirty flag so they are only recomputed when a transform actually changes. 

// Attach a child to a parent
scene->TransformComp.setParent(child, parent);

// World matrix is computed lazily — cache invalidated when any ancestor moves
glm::mat4 world = scene->TransformComp.getWorldMatrix(child);

SceneState: Play / Pause / Stop

Scene tracks an execution state through the SceneState enum: 

enum class SceneState { Stopped, Playing, Paused };

Calling scene->Play() serialises the current scene to a temp file, then reloads it fresh and starts script execution. Pause() freezes script updates but keeps rendering active. Stop() reloads the temp file to restore the exact pre-play state — identical to the Unity Play/Stop workflow.

DebugName and Editor Integration

DebugNameComponent stores a human-readable string per entity. The editor hierarchy panel uses these names for display, and the Lua scripting system exposes named entities as Lua globals so scripts can reference other objects by name without manual lookup: 

-- In player.lua: reference another named entity directly
local door = find("Door")
door.transform.translate(0, 0, 1)

Key Takeaways

  • Generational IDs prevent dangling handle bugs without garbage collection.
  • SoA component managers keep per-component iteration cache-friendly.
  • Dirty-flag caching on world matrices avoids redundant matrix multiply chains.
  • ScriptComponent bridges the ECS and Lua layers with zero engine recompilation.
