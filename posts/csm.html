Cascaded Shadow Maps (CSM)

Posted on April 25, 2026 · Tags: shadows · csm · vulkan · depth · lighting

A single shadow map covering the full view frustum is a poor trade-off: nearby surfaces need high texel density but distant terrain needs wide coverage. Cascaded Shadow Maps (CSM) solve this by splitting the view frustum into sub-ranges, each covered by its own depth map at the same resolution — giving high detail up close and acceptable quality at distance without any increase in total shadow map memory.

Constants

// From gh_vk_shadow_map.h
inline constexpr int   CSM_CASCADE_COUNT   = 3;
inline constexpr int   CSM_SHADOW_MAP_SIZE = 2048;   // pixels per cascade
inline constexpr float CSM_LAMBDA          = 0.75f;  // log/linear split blend
inline constexpr float CSM_NEAR_PLANE      = 0.1f;
inline constexpr float CSM_FAR_PLANE       = 300.0f; // world units

Split Distance Calculation

The frustum is divided into three sub-frustums. Each cascade boundary is computed as a weighted blend between a linear split (equal range per cascade) and a logarithmic split (more cascades near the camera, where shadow detail matters most). CSM_LAMBDA = 0.75 means 75% logarithmic, 25% linear: 

for (int i = 0; i < CSM_CASCADE_COUNT; ++i) {
    float p       = float(i + 1) / float(CSM_CASCADE_COUNT);
    float logSplit = nearPlane * pow(farPlane / nearPlane, p);
    float linSplit = nearPlane + (farPlane - nearPlane) * p;
    splits[i] = CSM_LAMBDA * logSplit + (1.0f - CSM_LAMBDA) * linSplit;
}
// Typical results: ~7 m, ~40 m, 300 m

Light-Space Matrices

For each cascade, a tight orthographic projection is fit around the cascade's sub-frustum corners in world space, then transformed to the light's view space. This minimises wasted shadow map space. The matrix and split distance are packed into the ShadowData UBO and uploaded to the GPU once per frame: 

// GPU-side struct (std140, 272 bytes total)
struct alignas(16) ShadowCascade {
    glm::mat4 lightSpaceMatrix; // world → light NDC (64 bytes)
    glm::vec4 splitFarAndPad;  // x = cascade far in view space (16 bytes)
};

struct ShadowData {
    ShadowCascade cascades[3]; // 240 bytes
    glm::vec4     lightDir;    // xyz = direction toward light
    float         constantBias;
    float         slopeBias;
    uint32_t      enabled;     // 0 = shadows off
    float         blendRange;  // cascade blend zone width
};

Vulkan Image Setup

The shadow atlas is a single VkImage with arrayLayers = 3 (one per cascade) in D32_SFLOAT format. Two types of image view are created from the same underlying allocation:

  • Three 2D per-layer views (VK_IMAGE_VIEW_TYPE_2D, baseArrayLayer = i, layerCount = 1) — used as framebuffer depth attachments during the three shadow sub-passes.
  • One 2D array view (VK_IMAGE_VIEW_TYPE_2D_ARRAY, layerCount = 3) — bound to the lighting pass descriptor so the shader can sample all three cascades at once. 
// Render shadow into cascade i
VkFramebufferCreateInfo fbInfo{};
fbInfo.renderPass      = shadowRenderPass_;
fbInfo.attachmentCount = 1;
fbInfo.pAttachments    = &shadowMap_.layerView(i);  // 2D per-layer view
// ...

// Bind combined array view to lighting descriptor
VkDescriptorImageInfo shadowInfo{};
shadowInfo.imageView   = shadowMap_.arrayView();    // 2D_ARRAY view
shadowInfo.imageLayout = VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL;
shadowInfo.sampler     = shadowMap_.sampler();      // comparison sampler

Image Layout Transitions

Vulkan requires explicit barriers between passes. After writing each cascade as a depth attachment, a pipeline barrier transitions it from DEPTH_STENCIL_ATTACHMENT_OPTIMAL to SHADER_READ_ONLY_OPTIMAL so the lighting pass can sample it safely: 

vk::ImageMemoryBarrier barrier{};
barrier.oldLayout     = vk::ImageLayout::eDepthStencilAttachmentOptimal;
barrier.newLayout     = vk::ImageLayout::eShaderReadOnlyOptimal;
barrier.srcAccessMask = vk::AccessFlagBits::eDepthStencilAttachmentWrite;
barrier.dstAccessMask = vk::AccessFlagBits::eShaderRead;
// subresource range covers all 3 array layers
cmd.pipelineBarrier(
    vk::PipelineStageFlagBits::eLateFragmentTests,
    vk::PipelineStageFlagBits::eFragmentShader,
    {}, {}, {}, barrier);

PCF Shadow Sampling in GLSL

The lighting shader uses a comparison sampler (created with compareOp = LESS_OR_EQUAL). texture(shadowSampler, uvw) returns a hardware-interpolated [0,1] value where 1.0 means fully lit. A small PCF kernel around the sample point smooths the shadow edge: 

layout(set = 0, binding = 3) uniform sampler2DArrayShadow shadowAtlas;

float sampleShadow(vec3 worldPos, vec3 N, uint cascade) {
    vec4 shadowCoord = cascades[cascade].lightSpaceMatrix * vec4(worldPos, 1.0);
    shadowCoord.xyz /= shadowCoord.w;
    shadowCoord.xy   = shadowCoord.xy * 0.5 + 0.5;

    // Bias: constant + slope-scale to prevent shadow acne on flat surfaces
    float bias = constantBias + slopeBias * (1.0 - dot(N, lightDir.xyz));

    float shadow = 0.0;
    vec2 texelSize = 1.0 / vec2(2048.0);
    for (int x = -1; x <= 1; ++x)
    for (int y = -1; y <= 1; ++y) {
        vec2 offset = vec2(x, y) * texelSize;
        shadow += texture(shadowAtlas,
            vec4(shadowCoord.xy + offset, float(cascade), shadowCoord.z - bias));
    }
    return shadow / 9.0;
}

Cascade Selection in the Shader

// Choose the tightest cascade that covers this fragment's depth
uint cascade = 0;
for (uint i = 0; i < 3; ++i) {
    if (viewDepth < cascades[i].splitFarAndPad.x) {
        cascade = i;
        break;
    }
}
float shadow = sampleShadow(worldPos, N, cascade);

Development Iterations

  • Iteration 1 — Single 4096×4096 map. Severe aliasing near the camera; unusable at default viewing distances.
  • Iteration 2 — Two cascades, split at 30 units. Near-camera quality acceptable but distant shadows aliased badly beyond 100 units.
  • Iteration 3 (current) — Three cascades, 2048×2048 each, logarithmic split (λ=0.75), far plane 300 units. Shadow bias exposed in the editor UI for per-scene fine-tuning.
