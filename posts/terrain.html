Procedural Terrain: fBm, Erosion & Vegetation

Posted on May 15, 2026 · Tags: terrain · procedural · noise · erosion · vegetation

GHost Engine's terrain system generates an infinite chunked landscape entirely at runtime — no heightmap file required. Artists control the appearance through noise parameters, erosion settings, and vegetation density, all adjustable live in the editor. The generation pipeline has five stages: domain warp, fBm accumulation, ridge blending, power curve, and erosion simulation.

Chunked Grid Architecture

The terrain is divided into square chunks. Each chunk is an independent GHModel with vertex positions computed from a deterministic height function. Resolution scales with LOD level: LOD 0 uses 64 vertices per side, LOD 1 uses 32, LOD 2 uses 16, and LOD 3 uses 8. Chunk edges are designed to align at all LOD levels so seams never appear between adjacent chunks.

Stage 1 — Domain Warp

Before evaluating the main noise, the sample position (x, z) is offset by a secondary noise field. This "warps" the coordinates, breaking the grid regularity that makes noise functions look artificial: 

// Domain warp: displace the sample point before main noise evaluation
glm::vec2 warpOffset = glm::vec2(
    stb_perlin_noise3(x * warpFreq, z * warpFreq, 0.0f, 0, 0, 0),
    stb_perlin_noise3(x * warpFreq, z * warpFreq, 5.2f, 0, 0, 0)
) * warpStrength;

float sx = x + warpOffset.x;
float sz = z + warpOffset.y;
// Use (sx, sz) for fBm evaluation instead of (x, z)

Stage 2 — Fractional Brownian Motion (fBm)

Six octaves of Perlin noise are summed, each at double the frequency and half the amplitude of the previous. Low-frequency octaves create large hills and valleys; high-frequency octaves add surface roughness and fine detail: 

float fbm(float x, float z, int octaves, float lacunarity, float gain) {
    float value     = 0.0f;
    float amplitude = 1.0f;
    float frequency = 1.0f;
    for (int i = 0; i < octaves; ++i) {
        value     += amplitude * stb_perlin_noise3(x * frequency,
                                                    z * frequency,
                                                    0.0f, 0, 0, 0);
        amplitude *= gain;       // default 0.5 (each octave half as loud)
        frequency *= lacunarity; // default 2.0 (each octave twice as detailed)
    }
    return value;
}
// Called with octaves=6, lacunarity=2.0, gain=0.5

Stage 3 — Ridge Blending

When ridge_blend > 0, the absolute value of the noise is mixed into the result. |noise| is zero at noise-crossings and non-zero elsewhere, which inverts the terrain into sharp V-shaped valleys and mountain ridges: 

// Ridge blend: produces sharp ridges and valleys
float h = fbm(sx, sz, 6, 2.0f, 0.5f);
if (ridgeBlend > 0.0f) {
    float ridge = 1.0f - std::abs(h); // invert: peaks where |noise|=0
    ridge = std::pow(ridge, ridgePower);
    h = glm::mix(h, ridge, ridgeBlend);
}

Stage 4 — Power Curve & Scale

A power function controls the distribution of flat plains versus steep mountains. A power > 1 pushes heights toward extremes (dramatic peaks and flat valleys). Finally, heightMultiplier converts the normalised [0,1] value to world units: 

// Normalise to [0,1] then apply power curve
float normalized = (h + 1.0f) * 0.5f;           // remap [-1,1] → [0,1]
float powered    = std::pow(normalized, power);  // redistribute
float worldHeight = powered * heightMultiplier;  // scale to world units

Stage 5 — Hydraulic Erosion

After the base heightmap is generated, a particle-based hydraulic erosion simulation runs for 50,000 iterations (configurable). Each virtual water droplet:

  1. Starts at a random position on the heightmap.
  2. Follows the steepest downhill gradient, accelerating with slope.
  3. Picks up sediment proportional to its speed and flow capacity.
  4. Deposits sediment where it slows down (flat areas, valley floors).
  5. Evaporates after a fixed number of steps.

After many iterations, V-shaped valleys erode into the terrain and alluvial fans accumulate at the base of slopes — closely matching real geological formations.

🖼 IMAGE: Terrain before and after hydraulic erosion Left: raw fBm terrain — smooth, rounded hills with no directional features. Right: after 50,000 erosion iterations — channels, ridges, and sediment fans visible. 
// Erosion droplet step (simplified)
struct Droplet { glm::vec2 pos, vel; float sediment, water; };

for (int i = 0; i < erosionIterations; ++i) {
    Droplet d{ randomPos(), {0,0}, 0.0f, 1.0f };
    for (int step = 0; step < maxSteps; ++step) {
        glm::vec2 grad   = gradient(heightmap, d.pos);
        d.vel            = d.vel * inertia - grad * (1.0f - inertia);
        float speed      = glm::length(d.vel);
        float capacity   = std::max(speed * d.water * sedimentCapacity,
                                    minCapacity);
        // Erode or deposit
        if (d.sediment > capacity) {
            float deposit = (d.sediment - capacity) * depositSpeed;
            heightmap[d.pos] += deposit;
            d.sediment       -= deposit;
        } else {
            float erode = std::min((capacity - d.sediment) * erodeSpeed,
                                   maxErosion);
            heightmap[d.pos] -= erode;
            d.sediment       += erode;
        }
        d.pos  += glm::normalize(d.vel);
        d.water *= (1.0f - evaporateSpeed);
        if (d.water < 0.01f) break;
    }
}

Thermal Erosion

Thermal erosion redistributes material from steep slopes to flat areas. For each cell, if the height difference to any neighbour exceeds the talus angle threshold, material is transferred downhill. This rounds off vertical cliffs and produces scree slopes at the base of steep terrain.

Vegetation Billboards

After terrain generation, random positions within each chunk are tested against a height and slope filter. Positions below the tree line and on gentle slopes receive a BillboardComponent entity. The billboard vertex shader computes the screen-facing orientation from the view matrix right and up vectors per vertex — no CPU sort is needed: 

// In the billboard vertex shader
vec3 right = vec3(view[0][0], view[1][0], view[2][0]); // view matrix right
vec3 up    = vec3(0.0, 1.0, 0.0);                      // world up (no tilt)

vec3 worldPos = center
    + right * localPos.x * scale
    + up    * localPos.y * scale;

Infinite Terrain Mode

In infinite mode, the system tracks the camera's chunk coordinates. Every frame, chunks within the view radius that don't yet exist are generated (dispatched to the job system as background tasks), and chunks that have left the radius are destroyed and freed. Because the height function is purely position-based (no grid snapping), newly generated chunks seamlessly continue the existing terrain with no visible seam.
