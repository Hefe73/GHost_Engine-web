HDR Pipeline & Tonemapping (ACES / Hable)

Posted on May 5, 2026 · Tags: hdr · aces · tonemapping · postprocess · vulkan

Physically-based lighting produces radiance values far above 1.0 — bright sunlight, specular highlights, and emissive surfaces can reach hundreds of times the intensity of a mid-grey surface. Storing this in an 8-bit render target would clip everything above 1.0, destroying highlight detail. GHost Engine keeps the lighting pass output in a 16-bit float HDR target and maps it to the display range in a dedicated post-processing pass.

HDR Render Target

The HDR format used throughout the engine is: 

// From gh_postprocess.h
static constexpr vk::Format HDR_FORMAT = vk::Format::eR16G16B16A16Sfloat;

16-bit float (half precision) per channel provides values from ~6×10⁻⁵ to ~65,504 — more than enough for PBR lighting while using half the memory of 32-bit float. Two independent HDR targets are maintained: hdrImage for the game viewport and hdrImageEditor for the editor viewport, so both can render simultaneously with different cameras.

PostProcessConfig

All post-processing parameters live in a plain struct that can be modified at any time from the editor UI or from a Lua script — changes take effect on the very next frame: 

struct PostProcessConfig {
    ToneMappingMode toneMappingMode = ToneMappingMode::ACES; // default
    float exposure = 1.0f;   // linear pre-multiplier before tonemapping
    float gamma    = 2.2f;   // power applied after tonemapping (sRGB correction)
};

Tonemapping Curves

Three curves are selectable at runtime via the editor panel or Lua:

Linear Clamp

// ToneMappingMode::Off
vec3 tonemap(vec3 hdr) { return clamp(hdr, 0.0, 1.0); }

Simplest option: values above 1.0 clip hard. Useful for debugging (shows raw HDR output) but produces blown-out highlights in outdoor scenes — not suitable for final renders.

ACES Filmic (default)

The Academy Color Encoding System filmic curve was developed for the film industry and has been adopted by Cyberpunk 2077, Horizon Zero Dawn, Final Fantasy XV, and many others. GHost Engine uses the Narkowicz 2015 real-time approximation: 

// ToneMappingMode::ACES
vec3 ACESFilm(vec3 x) {
    const float a = 2.51, b = 0.03, c = 2.43, d = 0.59, e = 0.14;
    return clamp((x * (a * x + b)) / (x * (c * x + d) + e), 0.0, 1.0);
}

It produces a gentle lift in shadows (natural shadow detail), a near-linear mid-tone, and a soft roll-off in the highlights. The result closely matches the visual character of photographic film.

Hable (Uncharted 2)

// ToneMappingMode::Hable
vec3 hableOp(vec3 x) {
    float A=0.15, B=0.50, C=0.10, D=0.20, E=0.02, F=0.30;
    return ((x*(A*x+C*B)+D*E) / (x*(A*x+B)+D*F)) - E/F;
}
vec3 Hable(vec3 hdr) {
    vec3 curr   = hableOp(hdr * 2.0);
    vec3 whiteS = hableOp(vec3(11.2));
    return curr / whiteS;
}

The Hable curve (presented by John Hable at GDC 2010 for Uncharted 2) gives stronger highlight compression and more saturated mid-tones — a high-contrast cinematic look preferred for stylised or action game art styles.

Full Post-Processing Shader

layout(push_constant) uniform PC {
    uint  mode;     // 0 = Off, 1 = ACES, 2 = Hable
    float exposure;
    float gamma;
} pc;

layout(set = 0, binding = 0) uniform sampler2D hdrInput;

void main() {
    vec3 hdr = texture(hdrInput, uv).rgb;

    // 1. Exposure
    hdr *= pc.exposure;

    // 2. Tonemapping
    vec3 ldr;
    if      (pc.mode == 1) ldr = ACESFilm(hdr);
    else if (pc.mode == 2) ldr = Hable(hdr);
    else                   ldr = clamp(hdr, 0.0, 1.0);

    // 3. Gamma correction (linear → sRGB)
    fragColor = vec4(pow(ldr, vec3(1.0 / pc.gamma)), 1.0);
}

The Full-Screen Triangle Trick

The post-processing pass — like the lighting pass — uses a single triangle that covers the entire screen. No vertex buffer is required. The vertex shader generates clip-space coordinates from gl_VertexIndex alone: 

// Vertex shader — generates a full-screen triangle from 3 vertices
void main() {
    vec2 positions[3] = vec2[](
        vec2(-1.0, -1.0),
        vec2( 3.0, -1.0),
        vec2(-1.0,  3.0)
    );
    gl_Position = vec4(positions[gl_VertexIndex], 0.0, 1.0);
    uv = positions[gl_VertexIndex] * 0.5 + 0.5;
}

Calling vkCmdDraw(cmd, 3, 1, 0, 0) draws the triangle without binding any vertex buffers, slightly reducing driver overhead per full-screen pass.

Resize Handling

When the window is resized, gh_postprocess::resize() destroys and recreates hdrImage and hdrImageEditor at the new extent, and updates the descriptor sets that reference those image views. The tonemapping pipeline itself is resolution-independent and does not need recreation.
